# 迭代纪律

一张密集的示意图从"能看"到"能发表"要 5–15 轮。TRACE Figure 1 走了 13 轮
（`examples/trace-figure1/ITERATION_REPORT.md` 有逐轮记录）。没有纪律的迭代会陷入两种死循环：
改了三处不知道哪处把图搞坏了；改好的版本被下一轮覆盖找不回来。

## 五条规则

### 1. 一次只改一处

一个 token、一个宽度、一段文字的切分。改完立刻渲染对比。
两处以上同时改，出了问题就要二分回退，比多渲染一次贵得多。

### 2. 永远看 2× 渲染，不看缩略图

```bash
uv run scripts/inspect_figure.py fig1.svg --width 2400
```

缩略图上看不见的问题：高亮块比文字基线高 2px、两张卡片右边距差 6px、箭头从气泡文字上穿过、
字重 500 和 600 混用。这些在审稿人的 PDF 阅读器里 200% 放大时全会暴露。

### 3. 四象限分开看

`inspect_figure.py` 把 2× 图裁成 TL / TR / BL / BR 四块（带 5% 重叠防止边缘漏掉）。
一次看一块，看完再看下一块。人眼对整图会自动"脑补对齐"，分块之后才会诚实。

在 Claude Code 里直接 `Read` 四张 PNG 让模型看——它比人更不会脑补。

### 4. 文件名带版本号，永不覆盖

```
fig1_v8.svg  fig1_v8.png
fig1_v9.svg  fig1_v9.png     ← 当前
fig1_v10.svg ...
```

`render.mjs` 里的 `OUT_SVG` 每轮手动改版本号。看着啰嗦，但 v8 比 v9 好的时候你会感谢自己。
JSX 源文件不需要版本号——git 管它。

### 5. 记迭代报告

`ITERATION_REPORT.md` 两个部分：

```markdown
## Timeline
| 版本 | 工具链 | 改了什么 |
|---|---|---|
| v8  | Satori | 迁移到 JSX；发现 emoji 豆腐块、gradient 不渲染 |
| v8c | Satori | 头像改成 div 画的 |
...

## What Went Wrong and How It Was Fixed
### 1. <症状>
**Symptom**: ...
**Resolution**: ...
```

报告的价值在第二部分：下一张图、下一个项目、下一个人，都从这里起步而不是从零踩坑。
本仓库的 `pitfalls.md` 和 `satori-figure/references/gotchas.md` 就是从 TRACE 的报告里长出来的。

## 每轮检查清单

按顺序过一遍，任一项不过就是本轮的改动目标：

- [ ] **文字溢出**：有没有单词被截断、超出容器
- [ ] **右边缘**：并列的气泡 / 卡片右边缘是否在同一条竖线上
- [ ] **基线**：高亮块、chip、行内图标是否与文字同一基线
- [ ] **箭头**：是否穿过任何文字或容器；是否从正确的锚点出发
- [ ] **行长平衡**：同一气泡内各行长度是否悬殊（最短行 < 最长行 60% 就要重切）
- [ ] **字号层级**：标题 / 正文 / 标签 / 注释是否只用了 3–4 个字号
- [ ] **对比度**：次要文字在浅色底上是否 ≥ 4.5:1
- [ ] **空白**：卡片内 padding 上下左右是否对称

## 什么时候停

连续两轮的改动理由是"我觉得这样更好看"而不是"这里有一个缺陷"——停。
把当前版本转 PDF 放进论文，剩下的留给审稿意见。

## 从探索到终稿的完整节奏

```
ImageGen 3 张候选 (5 min)
  → 挑一张的构图，用 starter.jsx 搭骨架 (30 min)
  → v1 渲染，过检查清单，发现 6 个问题
  → v2–v7 每轮修一个 (每轮 5 min)
  → v8 转 PDF 进 LaTeX，编译看版面
  → 改一轮 (v9)
  → 停
```

总计 2–3 小时。这就是"别人花几千块外包一周"的那张图。
